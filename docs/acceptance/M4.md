## 实现范围

| 设计项 | 位置 |
| --- | --- |
| 主机发现（§4）：入口 Base64 JSON（Bootstrap 客户端：不跟随重定向、256 KiB、20 s）；只接受 https 域名主机，跳过 IP；并发 2 个探测 `guest/comm/config`；缓存 `providers-cache/ziyoumao/bootstrap.json`（无令牌）；入口失败时用缓存 | `providers/ziyoumao/bootstrap.rs` |
| API 层（§5、§8）：ProviderApi 客户端（不跟随重定向、1 MiB、20 s、无 cookie），令牌按请求附加为 `Authorization: <原值>`；信封解析（2xx 且有 data 才成功）；401/403→AuthInvalid，429→RateLimited（按 Retry-After 等一次，≤60 s），5xx/网络错误 GET 退避 1 s、3 s；宽松数字 DTO | `providers/ziyoumao/api.rs`、`account.rs` |
| 登录（§6）：只发往一个已选主机、只用探测成功的出站路由、不重试；JSON 正文写入预分配、drop 时清零的缓冲；密码为 `Password(Zeroizing<String>)`，Debug 不输出；验证码/设备提示→NeedsUserAction；415/422→ProviderCompat；`is_recaptcha` 时附加提示 | `providers/ziyoumao/auth.rs`、`domain/redact.rs` |
| 会话（§6.2、§6.4）：SecretStore `Mirage/account/<id>/session`；启动后台验证（不阻塞连接）；只有 401/403 进入 ReauthRequired，网络/5xx 进入 NetworkUnavailable 并保留令牌；会话只发往 `trusted_hosts`；可信主机都不可达且入口出现新主机时提示“服务地址已变更，请重新登录” | `app/accounts.rs`、`providers/ziyoumao/mod.rs` |
| 订阅（§7）：`SubscriptionSource::ProviderAccount`；每次更新先 `getSubscribe` 取最新 URL（变化时写回 `Mirage/account/<id>/subscribe_url`），网络失败用缓存 URL，鉴权失败停止并提示重新登录；下载 UA 严格为 `clash-verge`、不跟随重定向、不带 Authorization；567→ProviderCompat；之后走通用管线 | `app/accounts.rs`、`app/updates.rs`、`subscriptions/fetch.rs` |
| 用量（§15）：服务商 API 的套餐、已用（u+d）、总量、到期优先于响应头；0/null 显示“未提供” | `domain/model.rs`、`app/accounts.rs` |

## 手工验收

登录/会话/订阅的各种响应用本地模拟面板 `target/m4-acceptance/zymserver.py`（`127.0.0.1:18081`，按 `login_mode`/`session_mode`/`sub_mode` 文件切换；debug 构建通过 `MIRAGE_ZIYOUMAO_BOOTSTRAP` 指向它，release 构建忽略该变量且只接受 https 域名）。服务器只记录方法、路径、UA、是否带 Authorization/Cookie 与请求体字段名。UI 通过 Windows UI Automation 驱动。

## 已知限制

- v1 UI 只支持一个自由猫账号（数据层支持多个）；再次登录覆盖同一账号并沿用其 Profile。
- 账号 API 的出站策略固定为 Auto，订阅下载的出站策略同普通订阅默认值；设置界面在 M5。
- 主机可信列表只在登录时增加；服务端更换全部主机后需要重新登录。
