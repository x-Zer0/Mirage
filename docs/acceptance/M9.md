# M9：用户覆写层、IPv6、测速去除握手延迟

日期：2026-10-22。环境：Windows 11 x64，Rust stable-msvc；官方 Mihomo Meta v1.19.32。设计依据 [iteration-2-design.md](../iteration-2-design.md) §1、§4、§5。未新增或运行单元测试。

## 实现范围

- `cores/mihomo/compose.rs`：新增 `UserOverlay { ipv6, unified_delay }`，`ManagedOverlay.user`。`compose()` 在摘要比对通过后执行 `apply_user`：
  - IPv6 开启 / 关闭：写顶层 `ipv6`，存在 `dns` 块时同时写 `dns.ipv6`；跟随订阅不改动。
  - 统一延迟开启：写 `unified-delay: true`；关闭不改动。
  - 覆写为默认值（跟随 + 关）时不重新序列化，输出与 M8 一致。
- `domain/model.rs`：`Ipv6Mode`（`follow` / `on` / `off`），设置页下拉顺序为跟随订阅、开启、关闭。
- `storage/meta.rs`：`settings.json` 新增 `ipv6`（默认 `follow`）、`unified_delay`（默认 `true`），旧文件兼容。
- `app/pipeline.rs`：导入与更新的 `-t` 校验使用空覆写，只判定订阅本身。
- `app/runtime.rs`：启动、热重载请求带 `user`；`Running.user` 记录运行中配置的覆写；新增 `reapply`（合成 + `-t` → 热重载 → 失败用原覆写重载，结果为 `Applied / Rejected / RolledBack / NeedsRestart`）。
- `app/overlay.rs`：`user_overlay()`、`sync_user_overlay()`、`on_overlay_applied()`。启动或订阅热重载进行中时延后，结束后自动补做。失败时恢复原设置、写“应用设置 / 失败”操作日志，不标记订阅版本无效。
- `app/settings.rs`：保存时识别覆写变化；同时修改端口 / 局域网时走原有重启路径（重启即使用新覆写），否则热重载，不重启内核。操作日志记录 `IPv6：A → B`、`测速去除握手延迟：开 → 关`。
- 设置页“网络”分区新增 IPv6 下拉框与“测速去除握手延迟（统一延迟）”勾选框，均带说明图标。
- 文档：DESIGN §9.3 补充用户覆写层，§10.7 并发数改为 16 并补充统一延迟口径，§17.1 设置页内容；iteration-2-design §1.1、§1.3 记录 M9 定稿实现。
- `mirage-ipc` / `mirage-svc` 未改动，`OVERLAY_VERSION` 仍为 3，TUN 服务无需更新。

## 手工验收清单

按用户安排，M9–M12 全部开发完成后统一手工验收；M9 先以静态检查通过为准提交。

前置：`cargo build --workspace --release -j 1`，按 README 复制 `core/`；准备一个可用订阅。run/config.yaml 位于 `%LOCALAPPDATA%\Mirage\run\config.yaml`，仅在连接期间存在。

| # | 步骤 | 期望 | 结果 |
| --- | --- | --- | --- |
| 1 | 旧 settings.json 升级启动 | 设置页 IPv6 显示“跟随订阅”，统一延迟为勾选；settings.json 保存后出现 `"ipv6": "follow"`、`"unified_delay": true` | 待统一验收 |
| 2 | 系统代理模式连接，统一延迟开、IPv6 跟随 | run/config.yaml 中 `unified-delay: true`；`ipv6` 与订阅原文一致 | 待统一验收 |
| 3 | 连接中把 IPv6 改为“开启”并保存 | 提示“正在热重载内核”→“设置已保存并热重载”；内核 PID 不变；run/config.yaml 中 `ipv6: true`，订阅有 `dns` 时 `dns.ipv6: true`；操作日志有“保存设置 / IPv6：跟随订阅 → 开启”和“应用设置 / 成功” | 待统一验收 |
| 4 | 改为“关闭”并保存 | `ipv6: false`、`dns.ipv6: false`（有 dns 时）；仍为热重载 | 待统一验收 |
| 5 | 改回“跟随订阅” | `ipv6` 恢复订阅原值；Mirage 不再写 `dns.ipv6`（订阅本身有的除外） | 待统一验收 |
| 6 | 统一延迟：开时测速记录一组节点延迟，关闭保存后再测（订阅未写 `unified-delay` 时） | 关闭后数值明显变高；开启后明显降低；每次修改都会清空旧测速结果 | 待统一验收 |
| 7 | TUN 模式（订阅未启用 DNS，注入最小 DNS），IPv6 设为开启 | 应用侧 run/config.yaml 含最小 DNS 且 `dns.ipv6: true`、`ipv6: true`；服务再执行策略后 `GET /configs` 中 `ipv6` 仍为 true，`nslookup -type=AAAA` 经 TUN 有应答；TUN 正常联网 | 待统一验收 |
| 8 | TUN 模式下切换 IPv6 / 统一延迟 | 走服务重载，不重启内核与网卡；`GET /configs` 中 `ipv6` 与设置一致 | 待统一验收 |
| 9 | 同时修改端口和 IPv6 | 只按原路径重启一次内核，重启后的 run/config.yaml 已含新 IPv6 值 | 待统一验收 |
| 10 | 未连接时修改 IPv6 / 统一延迟 | 只提示“设置已保存”；下次连接生效 | 待统一验收 |
| 11 | 订阅更新热重载后 | 新版本 run/config.yaml 仍带当前 IPv6 / 统一延迟覆写 | 待统一验收 |
| 12 | 放弃修改 | IPv6 与统一延迟恢复为已保存值 | 待统一验收 |

TUN 下 IPv6 的实际接管效果（iteration-2-design §9）：只在此记录观察结论，不在 UI 上标记为“已支持”。观察：待统一验收。
