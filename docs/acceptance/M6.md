## 2. 实现范围与本次修复

### 2.1 设计项落点

对照 DESIGN.md §20「M6 可靠性收尾」：诊断包、日志轮转、schema 迁移、冲突检测（§11.8）、开机启动。

| 设计项 | 位置 | 说明 |
| --- | --- | --- |
| 日志轮转（§18） | `crates/mirage-app/src/logging/mod.rs`、`crates/mirage-app/src/logging/rolling.rs` | 自研 `RollingWriter` 取代 `tracing-appender` 的滚动器：按日一文件、**单文件上限 10 MiB**、**保留 7 天**。超限时同日滚动出 `mirage-2026-10-16.1.log`（上限 `MAX_SEGMENTS`），轮转/启动时按文件名日期清理过期段。原有的整体脱敏写入层（`RedactingMakeWriter`）保持不变 |
| 内核日志同策略（§18） | `crates/mirage-app/src/cores/mihomo/process.rs`、`crates/mirage-app/src/app/runtime.rs`、`crates/mirage-app/src/storage/layout.rs` | 内核 stdout/stderr 改为 `Stdio::piped()` + tokio 任务泵入同一个 `RollingWriter`（两者共用一把锁）。`CoreCommand.log_file` 语义变为「滚动路径基名」（`Layout::core_log_stem()`），实际文件为 `core-<date>[-n].log` |
| 日志尾部读取 | `crates/mirage-app/src/logging/rolling.rs` `newest_segment`、`process::log_tail` | 内核早退时读取**最新一段**而非固定路径 |
| schema 迁移（§13） | `crates/mirage-app/src/storage/meta.rs` | `load` 先按原始 JSON 读 `schema_version`（缺字段视为 0），低于当前版本时→**先复制 `<name>.bak`**→按步迁移（`step()` 链，目前只有 0→1）→原子写回→反序列化。高于当前版本拒绝加载且不覆盖 |
| 旧文件兼容 | `crates/mirage-app/src/storage/meta.rs` | 各 `*File` 的 `schema_version` 加 `#[serde(default)]`；`Versioned` trait 只保留 `set_schema_version` |
| 冲突检测（§11.8） | `crates/mirage-app/src/platform/windows/conflict.rs` | 三项检测：① 进程 `ziyoumao.exe`/`ziyoumaoCore.exe`（ToolHelp32 快照）；② wintun 类网卡（`GetAdaptersAddresses`，匹配 friendly name/description 含 mihomo/meta/wintun）；③ 系统代理指向**其他本地端口**（本机端口有任一条命中自身即不算冲突）。**只提示、不结束对方进程** |
| 端口占用提示（§11.8） | `conflict::port_owner`、`crates/mirage-app/src/app/runtime.rs` `ensure_port_free` | `GetExtendedTcpTable(TCP_TABLE_OWNER_PID_LISTENER)` 找监听该端口的 PID → 进程名，写进 `PortInUse` 的用户可见原因 |
| 冲突提示时机 | `crates/mirage-app/src/app/session.rs` `connect()` | 用户主动连接时检测一次；命中则以气泡提示（窗口隐藏时弹托盘通知）出现，`notifying()`。**不阻断连接** |
| 开机启动（§11.6） | `crates/mirage-app/src/platform/windows/autostart.rs`、`registry.rs` | `HKCU\...\CurrentVersion\Run` 写入 `Mirage = "<exe>" --autostart`；`apply(wanted)` 幂等对齐。启动时修复一次；保存设置时按变化应用 |
| 注册表助手 | `crates/mirage-app/src/platform/windows/registry.rs` | `read_string`/`read_dword`/`write_string`/`delete_value` + `windows_version()` |
| 诊断包（§18） | `crates/mirage-app/src/app/diagnostics.rs`、`crates/mirage-app/src/storage/zip.rs` | 8 类条目，store（不压缩）ZIP，CRC-32 内联实现，未新增 crate |
| 设置项与界面 | `crates/mirage-app/ui/pages/settings.slint`、`crates/mirage-app/ui/pages/diagnostics.slint`、`crates/mirage-app/ui/app.slint`、`crates/mirage-app/src/ui_bridge/*` | 设置页「开机启动」勾选框；诊断页「导出诊断包」按钮 |
| 依赖变更 | `Cargo.toml` | 仅新增 `windows` crate 的 feature：`Win32_NetworkManagement_IpHelper`、`Win32_NetworkManagement_Ndis`、`Win32_Networking_WinSock`、`Win32_System_Registry` |

### 2.2 本次验收中发现并修复的缺陷

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | `conflict::legacy_processes` 把进程名集合转小写后，拿原样的 `"ziyoumaoCore.exe"`（大写 C）去匹配 | **`ziyoumaoCore.exe` 永远检测不到**，直接踩空 M6 验收要点 | 比较时对常量也做 `to_lowercase()`（`crates/mirage-app/src/platform/windows/conflict.rs`） |
| 2 | 诊断包导出只对**内核日志**过 `redact_text`，应用日志与 `profiles.txt` 的「最近失败原因」直接用磁盘原文 | 日志里出现 `?token=…` 或邮箱时**原样进入诊断包**——违反 §18/§14.3 硬性验收点 | 应用日志、内核日志、`profiles.txt` 的失败原因统一过 `redact_text`（幂等）（`crates/mirage-app/src/app/diagnostics.rs`） |
| 3 | `prune` 只识别新命名 `mirage-<date>.log`，不识别旧版 `tracing-appender` 的 `mirage.<date>.log` | 升级后旧日志**永远不会被清理**，与 §18「保留 7 天」不符 | 新增 `parse_legacy`，清理时新旧命名统一按日期判定（`crates/mirage-app/src/logging/rolling.rs`） |

### 2.3 诊断包内容（§18 全 8 项）

| 条目 | 内容 |
| --- | --- |
| `logs/mirage/<文件>` | 应用日志，最多取最新 3 个分段，每段尾部 ≤512 KiB（按行对齐截断，头部注明「只保留最后 512 KiB」） |
| `logs/core/<文件>` | 内核日志，同上，导出时再过一遍 `redact_text` |
| `settings.json` | 磁盘原文（过脱敏） |
| `profiles.txt` | 配置摘要：名称、来源类型（URL 只留 host）、活动版本、更新间隔、最近失败原因（过脱敏）；**不含 URL 与 SecretRef** |
| `check.txt` | 最近一次 `-t` 输出 + 合成器的安全调整（§9.5） |
| `system-proxy.txt` | **实时**读取的 WinINet 值（含 server/bypass/PAC） |
| `environment.txt` | Mirage 版本、Windows 版本、本地端口、内核版本行与路径、期望 SHA256 |
| `conflicts.txt` | 导出时刻的 §11.8 检测结果 |

`raw/*.bin` 与 `core-home/run/config.yaml` 不在包内。导出流程：说明对话框（§14.2）→ 取消静默返回 → 选择路径 → `spawn_blocking` 收集写盘（原子写）→ 完成提示。
