# M2 系统代理与恢复验收

日期：2026-10-15；环境：Windows 11（x64），Rust 1.95.0 stable-msvc，Slint 1.18.1，mihomo v1.19.32。测试前系统代理为另一客户端的 `127.0.0.1:7892`（ProxyEnable=1），测试后已恢复为该值。

## 静态检查

| 检查 | 结果 |
| --- | --- |
| `cargo fmt --check` | 通过 |
| `cargo check` / `cargo clippy --all-targets -- -D warnings` | 通过 |
| `cargo build --release` | 通过 |

## 实现范围

| 设计项 | 位置 |
| --- | --- |
| WinINet 读写（FLAGS/PROXY_SERVER/PROXY_BYPASS/AUTOCONFIG_URL，SETTINGS_CHANGED + REFRESH，仅默认 LAN 连接） | `platform/windows/sysproxy.rs` |
| 系统代理事务（§11.3：original/applied 先落盘 → 端口探测 → 写入 → Applied；关闭时只在 current == applied 时还原；original 指向本应用端口时还原为直连） | `app/sysproxy.rs` |
| 恢复日志 `recovery/sysproxy.json`、`recovery/core.json`（PID + 创建时间 + 映像路径） | `storage/journal.rs`、`app/runtime.rs` |
| 启动恢复（§11.5：UI 之前执行；还原系统代理、按身份结束残留内核、清理 check/ 与 run/config.yaml） | `app/recovery.rs`、`main.rs` |
| 内核监督重启（1s/3s/10s，最多 3 次；稳定运行 60 s 后重置计数；超过上限撤除系统代理并提示） | `app/supervise.rs` |
| 外部修改检测（每 5 s 比对；被改动后放弃日志、不再覆盖，本次连接内不再自动开启） | `app/supervise.rs` |
| 连通检测（经 mixed-port 请求 `generate_204`，与内核状态分开显示，可手动重测） | `app/connectivity.rs` |
| Quit / `WM_ENDSESSION` 清理（先撤系统代理再停内核，注销时同步等待最多 5 s） | `app/mod.rs`、`platform/windows/session.rs` |
| 设置 `settings.json`：系统代理开关、启动时自动连接 | `storage/meta.rs` |
| UI：总览页系统代理开关、连通状态；托盘“系统代理”勾选项、重启中状态 | `ui/pages/overview.slint`、`ui/app.slint` |

## 手工验收

| 场景 | 结果 |
| --- | --- |
| 连接后开启系统代理 | 已验证：WinINet 变为 `127.0.0.1:17896`；`sysproxy.json` 为 `state=applied`，`original` 为 `127.0.0.1:7892` |
| 用任务管理器方式（`Stop-Process -Force`）结束 Mirage | 已验证：内核随 Job 退出；系统代理暂留 17896 |
| 重新启动 Mirage | 已验证：UI 显示前还原为 `127.0.0.1:7892`，日志 `restore outcome=Restored`，recovery 目录清空，提示“上次未正常退出，已还原系统代理设置” |
| 结束内核进程（第 1 次） | 已验证：约 1 s 后自动重启（新 PID），系统代理保持不变 |
| 60 s 内连续结束内核 | 已验证：按 1s/3s/10s 重启 3 次；第 4 次退出后不再重启，系统代理还原为 7892，提示“代理内核已停止，已恢复系统网络设置” |
| 外部程序把代理改为 `127.0.0.1:7999` | 已验证：5 s 内检测到，日志 `system proxy changed by another program`，日志文件删除，不覆盖 |
| 外部修改后注销（模拟 `WM_QUERYENDSESSION` + `WM_ENDSESSION`） | 已验证：内核停止，代理保持 7999（未被还原） |
| 代理仍归本应用时注销 | 已验证：`WM_ENDSESSION` 19 ms 内返回，代理还原为 7892，内核停止，run/config.yaml 与 recovery 均已清理 |
| 连通检测 | 已验证判定逻辑：样例配置的节点指向不可用地址，显示“无法访问互联网（HTTP 502）”。真实节点下的可达结果待 M3/M4 用真实订阅确认 |
| 托盘“退出” | 与注销走同一清理路径（`shutdown_cleanup`）；待人工确认 |
| 总览页系统代理开关、托盘勾选项 | 待人工确认 |

注销场景通过向 `MirageSessionWatcher` 隐藏窗口发送消息模拟，未做真实注销/关机。

## 已知限制

- bypass 列表与 mixed-port 暂不可在设置页修改（设置页在 M5 完成）。
- `tun.json` 恢复属于 M7。
