# M11：附加规则

日期：2026-10-22。环境：Windows 11 x64，Rust stable-msvc；官方 Mihomo Meta v1.19.32。设计依据 [iteration-2-design.md](../iteration-2-design.md) §1、§3。未新增或运行单元测试。

## 实现范围

- `overrides/rules.rs`：`rules.yaml` 读写；`rules:` 列表解析（空文本 / 只有注释视为空，顶层只允许 `rules`）；单条校验：括号配对、≥3 段、已知类型（16 种可视化 + 其他 Mihomo 类型）、禁止 `MATCH`、参数只允许 `no-resolve` / `src`、CIDR / ASN / 端口 / NETWORK 内容格式；上限 2000 条、单条 1024 字符、错误最多列出 50 条。`build` 由可视化表单生成规则：单个 IP 补 `/32` 或 `/128`，按地址族自动选 `IP-CIDR` / `IP-CIDR6`，`no-resolve` 只对 IP 类生效。
- `compose.rs::prepend_rules`：附加规则插在订阅 `rules` 前（订阅没有 `rules` 时新建）；目标须为内置策略（DIRECT / REJECT / REJECT-DROP / PASS）、`proxies` 或 `proxy-groups` 中的名称，`RULE-SET` 的规则集须在 `rule-providers` 中，`SUB-RULE` 的子规则须在 `sub-rules` 中，否则跳过并生成“跳过 N 条附加规则：当前配置中不存在…”说明；含进程匹配且订阅 `find-process-mode: off` 时改为 `strict`。`Composed.user_notes` 单独返回这些说明。
- `settings.json`：`custom_rules_enabled`，默认 true。
- `app/overrides.rs`：Hosts 与附加规则共用保存流程（M10 的 `app/hosts.rs` 合并进来）：解析 → 覆写有变化时对选中配置的活动版本 `-t` → 写文件与开关 → 已连接时热重载；内核校验返回的跳过说明显示在标签顶部并附在提示中。操作日志“保存附加规则”。
- `ui_bridge/rules_editor.rs`：可视化工作副本（UI 线程 `VecModel`），上移 / 下移 / 删除 / 添加 / 编辑为同步回调；未做可视化改动时 YAML 沿用原文（保留注释）；YAML → 可视化切换先解析，失败不切换并显示错误；“放弃修改”恢复已保存内容；保存后用新的已保存内容重置工作副本。
- `ui/pages/rules.slint` 附加规则标签：启用开关、可视化 / YAML 切换、已保存条数、非规则模式提示、跳过说明、`ListView` 列表（序号、类型、内容、目标、上移、下移、编辑、删除；高级规则标“（高级）”且不可编辑）、YAML 编辑框（带示例占位）、错误列表、保存 / 放弃修改。
- `ui/app.slint` 规则弹层：类型下拉（16 种，带中文说明）、按类型的示例占位、IP 类显示 `no-resolve`、目标输入框 + 目标下拉（内置策略 + 当前运行配置的策略组，不含 GLOBAL）；即时校验，不通过时禁用“确定”并显示原因。
- 新增 Lucide 图标 `plus`、`pencil`、`arrow-up`、`arrow-down`（lucide-static 1.57.0）。
- 文档：DESIGN §9.3 白名单补齐 `rules` / `find-process-mode`、§13 `rules.yaml`、§17.1 规则页；iteration-2-design §3 M11 定稿与 §9 核验结论；根 README 功能列表。
