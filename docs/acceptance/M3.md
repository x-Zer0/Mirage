# M3 URL 订阅验收

日期：2026-10-16；环境：Windows 11（x64），Rust 1.95.0 stable-msvc，Slint 1.18.1，mihomo v1.19.32。测试期间系统代理开关关闭；测试前备份数据目录，测试后原样恢复（系统代理仍为另一客户端的 `127.0.0.1:7892`）。

## 实现范围

| 设计项 | 位置 |
| --- | --- |
| HTTP 客户端工厂（§12.1）：`no_proxy`、无 cookie、rustls（ring）+ `rustls-platform-verifier` 系统证书库、连接 10 s / 总计 60 s、仅 https 且无 userinfo、最多 5 次 https 重定向、流式累计 16 MiB 上限（不信任 Content-Length）、错误不带 URL | `net/mod.rs` |
| 出站策略（§12.2）：Direct / ViaLocalCore / Auto（直连网络错误或超时且内核运行时经 mixed-port 重试一次；HTTP 4xx/5xx 不重试） | `net/mod.rs`、`subscriptions/fetch.rs` |
| 通用下载器（默认 UA `clash-verge/v2.0.0 mihomo/1.19.32`，2xx 之外失败，200 仍需内容识别） | `subscriptions/fetch.rs` |
| 响应头（§15）：`subscription-userinfo`（expire=0 显示“未提供”）、`profile-update-interval`（用户未设置时采用）、`content-disposition` 默认名称 | `subscriptions/userinfo.rs` |
| SecretStore（§14.1）：Credential Manager `Mirage/<key>`，超过 2560 字节转 DPAPI 文件；完整订阅 URL 只存于此，`profiles.json` 只有 SecretRef 与主机名；删除 Profile 同步删除凭据 | `platform/windows/secret.rs` |
| 版本与回退（§8）：内容相同只更新元数据；先 detect 再落盘；候选以 Unchecked 保存，`-t` 失败标记 Invalid 且活动版本不变；保留最近 5 个 + active/last_good | `app/pipeline.rs`、`subscriptions/revisions.rs` |
| 热重载事务（§8 7–9、§16.4）：写 run/config.yaml → `PUT /configs?force=true` → `/proxies` 可读 → 恢复 selection；失败写回 last_good 再 reload，仍失败则重启内核；同一时刻只有一个 reload，新候选排队 | `app/runtime.rs`、`app/updates.rs`、`cores/mihomo/controller.rs` |
| 定时更新：每 60 s 检查到期 Profile（默认 24 h，0 = 仅手动；失败后最迟 1 h 重试）；下载最多 3 个并发 | `app/updates.rs`、`app/mod.rs` |
| 状态：`RuntimeStatus::Reloading`（运行中，正在应用新配置） | `app/state.rs` |
| UI：订阅链接输入（提交后清空，不在 UI 保留）、单个更新/全部更新、用量与到期、“更新失败（仍使用 … 的版本）”；列表项支持无障碍默认动作 | `ui/pages/profiles.slint`、`ui_bridge/` |

## 手工验收

测试服务器：`target/m3-acceptance/subserver.py`（`127.0.0.1:18080`，按 `mode` 文件返回不同内容）。debug 构建允许 `http://127.0.0.1` 以便本地测试；release 构建只接受 https。UI 通过 Windows UI Automation 驱动（`target/m3-acceptance/uia.ps1`）。

| 场景 | 结果 |
| --- | --- |
| 添加订阅（URL 含 `?token=`，含 YAML 锚点与合并键、`external-controller: 0.0.0.0:9090`、`allow-lan: true`） | 已验证：名称取自 `content-disposition`（“测试订阅”），显示“已用 3.0 GiB / 100.0 GiB · 到期 2027-01-01”，更新间隔采用服务端 12 h，服务器收到 UA `clash-verge/v2.0.0 mihomo/1.19.32`；policy_notes 记录 allow-lan / external-controller 覆盖 |
| 订阅 URL 存放 | 已验证：Credential Manager 中为 `Mirage/profile/<id>/url`；数据目录 JSON 与日志中搜不到 token |
| 连接后选择节点 n2，服务端新增节点 n3 后手动更新 | 已验证：内核 PID 不变（热重载），节点列表变为 n1/n2/n3，当前仍为 n2，提示“已更新并热重载，节点选择已恢复”，新版本成为 active 与 last_good |
| HTML 错误页 | 已验证：拒绝，“不是有效的配置：收到的是网页而不是配置”，不保存版本 |
| 空响应 | 已验证：拒绝，“内容为空” |
| 约 18 MiB 响应 | 已验证：拒绝，“内容过大：响应超过 16 MiB 上限” |
| Base64 节点链接列表 | 已验证：拒绝，“节点链接列表订阅暂不支持” |
| HTTP 500 | 已验证：拒绝，“服务器返回 HTTP 500” |
| `-t` 校验失败的配置 | 已验证：原始版本保存并标记 `invalid`，active/last_good 不变，内核继续运行（PID 不变），显示 mihomo 错误行 |
| 以上失败后的状态 | 已验证：Profile 显示“更新失败（仍使用 2026-10-16 00:32 的版本）：…”，节点数保持 3 |
| 内容未变化 | 已验证：提示“已是最新”，不新增版本 |
| Auto 出站：直连连接被拒且内核运行中 | 已验证：日志 `direct download failed, retrying via local core`，经本地内核重试一次（测试配置的节点不可用，结果为 HTTP 502，按策略不再重试） |
| 真实 https 地址（www.baidu.com） | 已验证：TLS 经系统证书库握手成功，内容被识别为网页而拒绝 |
| `http://` 地址 / 含 `user:pw@` 的地址 | 已验证：分别提示“只支持 https:// 地址”“地址中不能包含用户名或密码” |
| 自签名证书站点（self-signed.badssl.com） | 已验证：连接失败（未出现跳过校验的路径）；错误归为“网络错误：tls handshake eof”，未细分为 TLS 类别 |
| 定时更新 | 已验证：把 last_fetch 回拨 13 h 后启动，约 60 s 内日志 `subscription update started … manual=false`，新版本（2 节点）在未连接状态下直接成为 active |
| 删除订阅 Profile | 已验证：Credential Manager 中对应条目被删除 |
| 热重载失败回退 last_good / 回退也失败时重启内核 | 未实测（需构造 `-t` 通过但 reload 失败的配置）；代码路径见 `runtime::reload` |
| 真实机场订阅端到端 | 待 M4 用自由猫订阅确认 |

## 已知限制

- 每个 Profile 的 UA、更新间隔、出站策略暂只能用默认值（设置界面在 M5）。
- 启动时自动连接后的立即更新、订阅过期提醒尚未实现；到期 Profile 在启动约 1 分钟后由定时检查触发。
- 拒绝自签名证书时错误文案为“网络错误”，未细分为“TLS 证书或握手失败”（hyper 包装掉了 rustls 错误类型），M5 统一错误条时处理。
