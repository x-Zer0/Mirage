日期：2026-10-16；环境：Windows 11 Enterprise LTSC 2024（26100，x64，12 逻辑核），Rust 1.95.0 stable-msvc，Slint 1.18.1，mihomo v1.19.32。测试前备份数据目录。系统代理始终为另一客户端的 `127.0.0.1:7892`（测试期间 Mirage 的系统代理开关关闭，未改动系统代理）；原自由猫客户端（含 `ziyoumaoCore.exe` 的 TUN）在测试期间保持运行。UI 通过 Windows UI Automation 驱动；UI 线程响应用 `SendMessageTimeout(WM_NULL)` 每 50 ms 探测一次（脚本在 `target/m5-acceptance/`）。

## 手工验收

### 后台更新时 UI 不卡顿

UI 线程往返延迟（`WM_NULL`，每 50 ms 一次；release 构建，已连接，窗口可见）：

| 场景 | 采样 | p50 | p99 | 最大 | >100 ms |
| --- | --- | --- | --- | --- | --- |
| 空闲基线 | 127 | 0.7 ms | 1.1 ms | 15.3 ms | 0 |
| 自由猫订阅手动更新（真实服务：getSubscribe → 下载 → `-t` → 热重载 → 恢复节点选择） | 395 | 0.7 ms | 7.6 ms | 26.4 ms | 0 |
| 切换到 1200 节点的配置（停止内核 → 合成 → `-t` → 启动 → 读取组） | 221 | 0.7 ms | 7.3 ms | 20.2 ms | 0 |
| 1201 个成员的组测速（结果写回 1201 行） | 319 | 0.7 ms | 3.0 ms | 14.3 ms | 0 |

结论：已验证，后台下载、校验、重载和大列表更新期间 UI 线程最大停顿 26 ms，无卡顿。

### 隐藏窗口后 CPU 接近 0

进程 CPU 时间差（release 构建，12 逻辑核）：

| 场景 | 结果 |
| --- | --- |
| 已连接，窗口隐藏（关闭到托盘）60 s | 0 ms（0.000%） |
| 已连接，窗口最小化 30 s | 0 ms |
| 已连接，窗口可见、无流量 20 s | 16 ms（约 0.8 ms/s） |
| `--autostart` 启动（只有托盘）并自动连接，30 s | 16 ms |
| 对照：M4 release，`--autostart` 未连接，20 s | 0 ms |

与内核控制器的连接数（Mirage → 控制器端口）：可见时 4（`/traffic`、`/logs` 两条流 + 2 条 keep-alive）；隐藏后立即降为 2（两条流已断开），60 s 后 keep-alive 过期为 0。最小化时两条流保持（每秒一行），不重绘。结论：已验证。

### 验收中发现并修复的问题

| 问题 | 修复 |
| --- | --- |
| Toast 没有自身尺寸，显示时覆盖整个内容区 3.5 s | Toast 按内容的 preferred 尺寸布局（`ui/components/error-bar.slint`），复测为底部小提示条 |
| 连接失败时状态文字带出内核日志尾部，撑满总览标题和侧栏 | 状态只显示错误类型（“连接失败：端口被占用”“连接失败：内核多次意外退出”），细节留在错误条；标题与侧栏单行省略 |
| 配置详情面板空白处的点击穿透到行，会切换活动配置并重启内核 | 详情面板外包一层吞掉点击的区域 |
| 任何错误都会把托盘图标变为错误状态 | 托盘错误状态只由内核状态决定 |
| 离开节点页再回来时搜索框被清空，列表却仍按旧搜索词过滤 | 搜索词与当前选项卡保存在窗口级属性中 |
| 配置详情的更新间隔、下载出站和设置页的“自由猫账号请求出站”在 UI Automation 中没有名称 | 补 `accessible-label` |

### 渲染器对比（DESIGN §22，M5 决定）

同一源码分别以 Slint 默认特性（femtovg + software 回退）和仅 software 渲染器构建 release，窗口可见、总览页、已连接（自由猫配置），用同一脚本测量：

| 指标 | femtovg（默认特性） | software（仅软件渲染） |
| --- | --- | --- |
| `Mirage.exe` 大小 | 19,379,200 B | 18,888,704 B |
| 进程加载的图形驱动 | `opengl32.dll`、`nvoglv64.dll` | 无 |
| 工作集 / 私有内存 | 88–89 MB / 131–132 MB | 43 MB / 15 MB |
| 可见、空闲 20 s CPU | 0–281 ms（有健康检查流量刷新曲线时 281 ms） | 0 ms |
| 可见、下载中（曲线每秒刷新）15 s CPU | 234 ms（15.6 ms/s） | 47 ms（3.1 ms/s） |
| 下载期间 UI 线程 p99 | 1.1–1.4 ms | 0.9–1.1 ms |
| 画面 | 与 software 一致（截图对比） | 与 femtovg 一致 |

决定：只启用 software 渲染器（`Cargo.toml` 中 Slint 关闭默认特性，保留 `std`、`backend-winit`、`renderer-software`、`accessibility`、`compat-1-2`、`system-tray`）。理由：不加载 OpenGL 驱动，远程桌面、虚拟机、无 GPU 驱动的环境同样可用（默认特性下 femtovg 只在创建渲染器失败时回退，窗口恢复阶段的 GL 失败未必触发回退）；内存少约 45 MB 工作集、约 115 MB 私有内存；本应用界面以静态内容为主，局部重绘的 CPU 更低。未测：大列表快速滚动的软件渲染开销（合成的滚轮消息驱动不了 winit 的滚动），留待真机手动观察，必要时再评估 skia。

## 已知限制

- 托盘通知借用 Slint 1.18 托盘的内部窗口（类名 `SlintSystemTrayWindow`、图标 id 1）实现，升级 Slint 时必须复核；失败时只记 warn 日志。
- Windows 11 默认把新托盘图标放在溢出区，托盘提示文字（含当前配置与出口节点）只能在溢出区或用户固定图标后看到，本次以菜单截图和代码路径验证托盘状态。
- 窗口最小化时 `/traffic`、`/logs` 保持连接（不重绘，实测 CPU 为 0）；只有关闭到托盘才断开。
- 自由猫节点今天的组测速全部超时（经节点的出站在本机当前网络下失败，与 UI 无关），延迟排序用含 DIRECT 的测试配置验证。
- 设置页的“开机启动”、诊断页的“导出诊断包”、应用日志级别临时切换（§18）在 M6 实现；TUN 开关与服务安装在 M7 实现，当前为禁用的占位。
- v1 UI 仍只支持一个自由猫账号（M4 限制不变）。
