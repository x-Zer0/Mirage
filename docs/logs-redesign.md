# 日志菜单实现说明

日期：2026-10-18。日志菜单已按确认的日志列表方案实现。

## 用户确认的范围

- 左侧“诊断”改为“日志”，页面包含“连接日志”和“配置日志”两个标签页。
- 连接地址显示域名或 IP 加端口；一条 Mihomo TCP/UDP 路由事件对应一条记录。
- 连接日志只保留 Mirage 本次运行期间的内存记录；窗口隐藏到托盘后持续采集；切换配置、热重载及重新连接后保留历史，配置切换期间显示采集暂时中断。设置页可配置保留条数，默认 1,000 条，允许 0–10,000；设置为 0 时停止记录并清空当前内存历史。清空只清除当前内存历史。
- 配置日志按日 JSON 文件跨重启保留设置的天数，默认 30 天，允许 0–60 天；设置为 0 时停止记录并清空已有配置日志。启动和运行期间清理过期记录；边界日期只重写未过期部分。
- 诊断原始日志不在界面展示，仅保留脱敏诊断包导出。
- 不读取旧的 `operation-logs.json` 或旧诊断 UI 数据；此阶段直接使用新结构。

## 连接日志行为

应用层通过 Mihomo `/logs?level=info` 读取 JSON 日志中的 TCP/UDP 路由事件。固定内核 v1.19.32 已验证的事件包括（代理场景使用两个本机内核组成隔离代理链，未使用真实账号）：

```text
[TCP] 127.0.0.1:54103 --> 127.0.0.1:19898 match Match using DIRECT
[TCP] 127.0.0.1:63747 --> 127.0.0.1:19385 using DIRECT
[TCP] 127.0.0.1:62464 --> 127.0.0.1:19389 match Match using Local Group[Local Node]
[TCP] 127.0.0.1:54105 --> ads.example.invalid:80 match Domain(ads.example.invalid) using REJECT
[TCP] dial DIRECT (match Match/) 127.0.0.1:54106 --> 127.0.0.1:19899 error: dial tcp ... actively refused it.
```

每条记录保存发生时间、协议、来源地址、目标地址、处理方式、易读规则、策略链、节点和当时配置名称/ID/版本快照。直连和拦截不填写伪造节点；内核没有提供的入口、进程和连接 ID 显示“未提供”。并发连接不会按地址和时间窗口合并。

`/traffic` 只在窗口可见时提供图表数据；连接日志流在内核运行期间持续，即使窗口隐藏到托盘也不停止。连接流使用运行代次隔离，旧配置事件不会写入新配置上下文。连接访问事件在应用和 TUN 服务写入持久化内核日志前按行过滤，避免访问记录进入诊断包。

页面支持关键词搜索、处理方式筛选、暂停滚动和清空。列表由 Slint `ListView` 虚拟滚动，不分页；暂停只固定视图，采集继续。连接记录采用紧凑四列双行，列宽为 10% / 30% / 30% / 30%，全部左对齐并对超长内容省略：时间/协议、地址、处理方式/规则、配置/节点。滚动离开顶部时暂停自动滚动，回到顶部后自动恢复。


## 连接日志存储评估

连接日志只需要覆盖当前运行，并且已经由 `VecDeque` 限制为设置的条数（默认 1,000，最大 10,000）。按每条记录约 0.5～2 KiB 的字符串和结构开销估算，完整历史通常约 5～20 MiB；订阅名称、规则和节点名称较长时仍有明确上限，不会随运行时间无限增长。界面只用 `ListView` 创建可见行，10,000 条记录不会同时创建 10,000 个控件。

因此当前采用内存环形缓冲，不把连接事件写入磁盘。一次性预分配磁盘区域并顺序写入并不能降低这部分需求的复杂度：仍需要固定编码、索引、循环覆盖、崩溃恢复、清空和配置切换边界处理，实时刷盘还会增加磁盘写入和故障面。连接日志也没有跨重启保留的产品需求，落盘收益不足以抵消这些成本。

如果未来需要跨重启连接历史，再评估追加式二进制环形文件或 SQLite/WAL，并以可查询索引和损坏恢复为前提；当前不提前引入磁盘连接日志，也不读取旧格式。
## 配置日志范围

配置日志由 AppCore 在业务结果落定后写入，页面采用 40% / 50% / 10% 三列双行布局，时间、操作摘要和结果均左对齐并对超长内容省略，包含：

- 新增 URL、账号订阅和本地配置，记录名称、来源和节点/组/规则数量。
- 手动和自动订阅更新，区分进行中、已是最新、成功、下载失败、配置应用失败、回退和保存失败。
- 配置切换、删除、路由模式和更新策略修改。
- 连接、断开、自动恢复、内核异常退出、系统代理、TUN 服务、规则数据更新和关键设置保存。

异步更新使用操作 ID；应用退出时仍处于“进行中”的记录会标记为中断失败。配置日志只写入脱敏后的摘要，不主动记录订阅 URL、令牌或密码；连接日志本身包含访问地址，仅保存在本次运行内存中。

## 代码落点

- `crates/mirage-app/src/app/logs.rs`：连接记录、操作记录、Mihomo 事件解析和规则名称转换。
- `crates/mirage-app/src/app/live.rs`：持续连接流、流重连、运行代次隔离和配置快照。
- `crates/mirage-app/src/app/log_actions.rs`：内存历史、搜索、筛选和配置日志写入。
- `crates/mirage-app/src/storage/operation_logs.rs`：按日持久化和动态天数清理。
- `crates/mirage-app/ui/pages/logs.slint`：日志列表 UI。
- `crates/mirage-ipc/src/core_log.rs`：应用和 TUN 服务的连接事件持久化过滤。
- `crates/mirage-app/src/app/diagnostics.rs`：复用现有脱敏诊断包导出。
