# 窗口布局与连通性修复

## 网卡名称评估

本次保留官方 Mihomo v1.19.32 二进制，没有改内核、驱动或系统网卡注册信息。

- 连接名称 `Meta` 可通过 Mihomo 的 `tun.device` 设置，属于配置调整。
- 设备描述 `Meta Tunnel` 不能视为同一个配置项。此次未能核实官方内核是否支持配置该描述，不能承诺只改配置即可变成 `Mirage Tunnel`。
- 完整更名若需修改 Mihomo 或 TUN 依赖，会增加自编译内核、更新哈希、服务校验、打包和后续内核升级维护工作。按用户要求不采用该方案，本次不实施网卡改名。

## 布局修复

- 保留原有 200px 侧栏、24px 内容边距、配色、卡片和按钮样式。
- 总览、账号、设置、诊断按自然内容高度滚动；配置和节点使用页面自身的 ListView，避免外层滚动挤压列表。
- 总览、诊断的双卡片由 GridLayout 排列，内容宽度小于 700px 时上下堆叠，不再混用手动坐标和自动布局。
- 配置条目在同一布局中分配文字和右侧操作按钮，展开详情置于下一行，条目高度随内容变化；安全调整说明过多时独立滚动。
- 账号页在正常宽度下保持右侧操作按钮，窄窗口才移到下一行。
- 节点组横向滚动，组说明与搜索、排序、测速分行；节点名称可以省略，保留右侧延迟。
- 设置端口提示分行，标签随宽度调整，长说明换行，可滚动到保存和内核服务区域。
- 诊断日志根据顶部信息及底部操作的实际高度分配空间；窄窗口下整页可滚动，日志仍保留 ListView 虚拟化。

## 连通性与恢复显示

- 重启流程重置连通性状态；手动刷新取消前一次检测，结果校验内核代次和请求编号，避免过期结果覆盖。
- 检测复用已有本地内核 HTTP 客户端，由外层 10 秒超时结束等待状态。
- 显示、恢复焦点、解除遮挡和尺寸恢复后延后触发表面重绘；托盘点击最小化窗口时恢复窗口。
- 补齐诊断导出按钮的状态及回调绑定。

## 验证范围

使用加载实际 ui/app.slint 的独立 Windows 界面预览，以示例账号、长配置名称、8 个节点组、每组 100 个节点和诊断数据检查布局。预览不启动代理内核，不读取实际账号或订阅，不更改系统网络设置。

- 760×520：逐页检查六个页面；检查总览及设置到底部的滚动、配置详情展开、节点组横向滚动和长列表、诊断顶部及底部。
- 1000×680：检查总览、配置详情、账号右侧按钮、诊断双卡片及完整底部区域。
- 1400×900：检查总览、诊断和节点页的宽窗口排列；另检查诊断页最大化显示。

静态验证使用 Cargo check、Clippy（警告作为错误）、rustfmt 和 diff 空白检查；未新增或运行单元测试。实际应用使用 Cargo build 编译。

界面预览只验证布局；本次没有以真实账号和订阅验证网络连通性，也未覆盖所有 DPI 或实际托盘恢复场景。
